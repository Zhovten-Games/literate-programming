# Companion

This companion presents an Org Babel literate workflow around one canonical plain-text source: `primes.org`.

## Source model and compact pipeline

Org Babel source:

- `primes.org` (canonical Org/Org Babel literate source)

Machine branch:

- `primes.org -> emacs --batch / org-babel-tangle -> primes.cpp -> g++ -> primes -> output.txt`

`primes.cpp` is generated by Org Babel tangling. Unlike `02-noweb-like`, `primes.cpp` here is a local generated artifact and should normally be ignored unless intentionally committed for demonstration. The compiler sees only `primes.cpp`; it never sees Org markers.

## What Emacs / Org-mode / Org Babel are

Emacs is a programmable text editor and extensible text/work environment. In this companion, Emacs is used not only as a visual editor, but as the processing engine that runs Org Babel in batch mode.

Org-mode is Emacs's structured plain-text document mode.

Org Babel is the Org-mode subsystem for source blocks: naming, references, tangling to source files, execution, and export.

Compact formula:

- Emacs: programmable editor / extensible text environment
- Org-mode: structured plain-text documents
- Org Babel: code blocks + tangling + execution + export

## Machine branch commands (tested WSL route)

```bash
emacs --batch primes.org -l org -l ob-tangle --eval '(org-babel-tangle-file "primes.org")'
g++ -std=c++17 -Wall -Wextra -pedantic primes.cpp -o primes
./primes > output.txt
grep "Page 1" output.txt && grep "Page 5" output.txt && grep "7919" output.txt
```

Successful tangling marker:

- `Tangled 1 code block from primes.org`

Expected program output markers:

- `The First 1000 Prime Numbers --- Page 1`
- `The First 1000 Prime Numbers --- Page 5`
- `      6571      6997      7499      7919`

## Optional readable/export branch

Org-mode can export documents, and Org Babel can be part of executable/literate documentation workflows.

Readable/export branch:

- `primes.org -> Org export -> readable document formats`

This companion verifies the tangling/build path. Export is part of the broader Org ecosystem but is not required for this prime-example smoke check.

## Markers and block syntax (Org Babel)

- `* Heading` creates document structure.
- `#+name: constants` names a source block.
- `#+begin_src cpp` starts a C++ source block.
- `#+end_src` ends a source block.
- `:tangle primes.cpp` tells Org Babel where to write generated code.
- `:noweb yes` enables noweb-style expansion.
- `<<constants>>` references a named block.
- `org-babel-tangle-file` expands references and writes tangled output.

The C++ compiler receives only tangled `primes.cpp`, not the `.org` document.

## Why not just comments?

Ordinary comments:

- explanation attached to code.
- source remains mostly code-first.

Org Babel:

- code blocks live inside a structured explanatory document.
- named blocks can be introduced where they make sense for the reader.
- tangling extracts machine-oriented source.

Short formula:

- Ordinary comments: explanation attached to code.
- Org Babel: code organized inside a structured document, then extracted for the machine.

## Windows notes

Emacs can be installed natively on Windows.

- GNU Emacs download page documents installer/zip options.
- Windows binaries are available from GNU mirrors/FTP.
- Recommended direct directory for this project: <https://ftp.gnu.org/gnu/emacs/windows/>.
- With zip-based installation, `bin\runemacs.exe` can be used.

If Emacs is not in PATH, PowerShell will not find it automatically.

```powershell
where.exe emacs
emacs --version
```

If not found:

- add Emacs `bin` to PATH, or
- run `emacs.exe` by full path, for example:

```powershell
& "C:\path\to\emacs\bin\emacs.exe" --batch primes.org -l org -l ob-tangle --eval "(org-babel-tangle-file \"primes.org\")"
```

Native Windows tangling may work, but native Windows compilation also needs a separate C++ toolchain (for example MSYS2/MinGW-w64 or Visual Studio Build Tools). For this companion, the primary reproducible route remains WSL/Linux for full chain verification.

## Editor / VS Code note

`primes.org` can be opened and edited in other editors, including Windows editors and VS Code with Org-related extensions. This is auxiliary editing support.

The reproducible workflow in this companion uses Emacs batch mode as the Org Babel processor. If a project does not want to adopt Emacs/Org-mode as an environment, `02-noweb-like` is usually the cleaner practical choice. If the goal is a historical full tangle/weave model, `01-cweb` is the better reference point.

## Troubleshooting notes

During first batch runs, Emacs may print:

```text
Could not read ‘org-id-locations’ from ~/.emacs.d/.org-id-locations, setting it to nil
```

For this companion this is not a build failure; it means the local Org ID cache file does not exist yet. The key success marker is still:

- `Tangled 1 code block from primes.org`

Line-ending note for Windows/WSL mixed editing: keep `.org` and generated `.cpp` with LF endings if CR artifacts appear.

```bash
sed -i 's/\r$//' primes.org
emacs --batch primes.org -l org -l ob-tangle --eval '(org-babel-tangle-file "primes.org")'
```
