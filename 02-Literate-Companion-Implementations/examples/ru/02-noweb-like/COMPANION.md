# Companion

Этот companion показывает практичный noweb-like workflow для одного noweb-like-источника: `primes.nw`.

## Модель исходника и компактный pipeline

noweb-like-источник:

- `primes.nw` (канонический literate-источник)

Машинная ветка:

- `primes.nw -> notangle -Rprogram -> primes.cpp -> g++ -> primes -> output.txt`

Читаемый/документационный слой в этом упрощённом companion:

- читаемый/документационный слой — это сам исходный файл `primes.nw`.
- обязательного второго сгенерированного PDF/HTML-документа в этом примере нет.

`primes.cpp` намеренно закоммичен как демонстрация результата tangling и должен совпадать с:

```bash
notangle -Rprogram primes.nw > /tmp/primes-from-noweb.cpp
diff -u primes.cpp /tmp/primes-from-noweb.cpp
```

Почему это важно: это более «чистое» практическое ядро literate programming без полного CWEB/TeX-ритуала. Здесь сохраняются именованные чанки, объяснительный порядок, корневой чанк и явный tangling в машинно-ориентированный исходник; при этом убираются CWEB-специфичные соглашения о маркерах, обязательный `cweave`, требования к TeX-макросам и генерация PDF как обязательный второй этап.

## Машинная ветка: ориентация на компилятор

```bash
notangle -Rprogram primes.nw > /tmp/primes-from-noweb.cpp
diff -u primes.cpp /tmp/primes-from-noweb.cpp
g++ -std=c++17 -Wall -Wextra -pedantic primes.cpp -o primes
./primes > output.txt
grep "Page 1" output.txt && grep "Page 5" output.txt && grep "7919" output.txt
```

Ожидаемые маркеры в выводе:

- `The First 1000 Prime Numbers --- Page 1`
- `The First 1000 Prime Numbers --- Page 5`
- `      6571      6997      7499      7919`

## Необязательная читаемая ветка

В классическом noweb есть и `noweave`, поэтому отдельный читаемый вывод возможен:

- `primes.nw -> noweave -> читаемый вывод в стиле TeX/LaTeX/HTML`

Но этот companion намеренно демонстрирует более лёгкий tangle-only путь, где `primes.nw` сам остаётся читаемым документом.

## Маркеры и синтаксис чанков (noweb)

- `<<program>>=` определяет именованный чанк с именем `program`.
- `<<name>>` ссылается на другой именованный чанк.
- `@` завершает текущий чанк.
- `notangle -Rprogram` выбирает `program` как корневой чанк.
- `notangle` разворачивает ссылки на чанки и генерирует обычный C++.
- C++ компилятор никогда не видит noweb-маркеры; он видит только сгенерированный `primes.cpp`.

## Почему не просто комментарии?

Обычные комментарии:

- объяснение прикреплено к коду.
- исходник остаётся в основном code-first.

noweb-like:

- код организован внутри объяснительного источника.
- именованные чанки можно вводить в порядке, удобном для понимания человеком.
- `notangle` собирает эти чанки в машинно-ориентированном порядке.

Короткая формула:

- Обычные комментарии: объяснение прикреплено к коду.
- noweb-like: код организован внутри объяснительного источника, а затем извлекается для машины.

Такой вариант часто проще поддерживать в современных проектах, потому что у него меньше «церемониальности», чем у CWEB. Именованные чанки напоминают паттерны, которые разработчики уже знают по блокам кода в Markdown, документационно-ориентированным примерам, ячейкам notebook-документов и executable documents. Это делает подход удобным для небольших демонстраций, алгоритмических заметок, учебных материалов и точечных эталонных реализаций.

Сбалансированная оговорка: CWEB исторически ближе к Knuth и сильнее как полноценная tangle/weave-система; noweb-like легче и лучше подходит как основной C++-пример перезапуска идеи в этом companion-наборе.

## Место в наборе

`02-noweb-like` — лёгкое практическое ядро набора и основной минимальный C++ reboot-пример. Он сохраняет именованные чанки и tangling, но избегает полного CWEB/TeX-ритуала. Полное сравнение всех companion-вариантов см. в корневом README.

## Установка: проверенный маршрут Debian/Ubuntu/WSL

Этот workflow в первую очередь Unix-like. На Windows практичный путь — WSL.

Установка инструментов:

```bash
sudo apt update
sudo apt install noweb build-essential
```

Проверка:

```bash
command -v notangle
command -v noweave
```

Опционально:

```bash
notangle -V
```

`notangle -V` не обязателен; важная проверка — что `command -v notangle` возвращает путь.

`noweb` часто не установлен по умолчанию. По возможности лучше ставить из пакета ОС. В upstream README также рекомендуется пакетная установка, потому что сборка из исходников может быть устаревшей, хрупкой и избыточно сложной.

Примечание про line endings (Windows/WSL): CRLF в `.nw` может давать визуальный шум в diff или CR-артефакты в результате tangling. В этом companion-каталоге `.nw` и сгенерированный `.cpp` должны быть в LF. При необходимости:

```bash
sed -i 's/\r$//' primes.nw
notangle -Rprogram primes.nw > primes.cpp
```

Также в этом каталоге используется `.gitattributes`, чтобы удерживать нужные файлы в стабильном LF-формате.

## Какие файлы появляются

- `COMPANION.md`  
  Документация этого companion-примера. Коммитится в репозиторий.
- `primes.nw`  
  Канонический noweb-like literate-источник. Коммитится в репозиторий.
- `primes.cpp`  
  Генерируется командой `notangle -Rprogram primes.nw`. Намеренно закоммичен как пример tangled-output. Не редактировать вручную, кроме случаев регенерации/синхронизации примера.
- `primes`  
  Скомпилированный исполняемый файл. Игнорируется.
- `output.txt`  
  Локально сохранённый вывод программы для smoke-check. Игнорируется.

В отличие от `01-cweb`, этот упрощённый companion не производит `primes.tex` или `primes.pdf` как часть обязательного workflow.
