# Companion

This companion shows a practical CWEB workflow for one literate source file: `primes.w`.

## Two-branch pipeline

CWEB source:

- `primes.w`

Machine branch:

- `primes.w -> ctangle -> primes.c -> cc/gcc -> primes -> output.txt`

Human-readable branch:

- `primes.w -> cweave -> primes.tex -> pdftex -> primes.pdf`

## Machine branch (compiler-oriented)

```bash
ctangle primes.w
cc -Wall -Wextra -pedantic primes.c -o primes
./primes > output.txt
grep "Page 1" output.txt && grep "Page 5" output.txt && grep "7919" output.txt
```

`ctangle` resolves CWEB section references and emits ordinary C code into `primes.c`. The compiler then works with plain C only.

## Human-readable branch (document-oriented)

```bash
cweave primes.w
pdftex primes.tex
```

This produces a readable document (`primes.pdf`) from the same source.

## CWEB markers: what they do

- `@` is the CWEB control prefix.
- `@*` starts a major section in the woven document.
- `@c` starts a program fragment used by `ctangle`.
- `@<Section name@>` references a named code fragment.
- `@ @<Section name@>=` defines a named code fragment.
- `ctangle` replaces section references with their definitions and generates normal C code.
- The C compiler never sees CWEB markers; it only sees the generated `primes.c`.

## Why not just comments?

Ordinary comments:

- explanation attached to code.
- human text is added around code, but source order stays mostly code-first.

CWEB:

- code organized inside an explanatory source, then extracted for the machine.
- named fragments can be introduced in the order of human understanding.
- `ctangle` assembles those fragments into compiler-oriented order.

## Place in the set

`01-cweb` is the historical C-family route closest to Knuth's WEB idea. It demonstrates the full tangle/weave split: machine-oriented source generation and human-readable documentation generation. For the full comparison of all companion variants, see the root README.

## Installation notes (tested Debian/Ubuntu/WSL route)

This workflow is primarily Unix-like. On Windows, WSL is a practical option.

Install core tools:

```bash
sudo apt update
sudo apt install texlive-binaries build-essential
```

Verify:

```bash
command -v ctangle
command -v cweave
ctangle --version
```

For PDF generation, `pdftex primes.tex` may initially fail with:

```text
I can't find file `cwebmac`.
```

Tested fix on Debian/Ubuntu/WSL:

```bash
sudo apt install texlive-extra-utils texlive-formats-extra
kpsewhich cwebmac.tex
```

Then run:

```bash
cweave primes.w
pdftex primes.tex
```

Package names above are the tested Debian/Ubuntu/WSL route and are not claimed to be universal for all distributions.

## Generated files (after running both branches)

- `COMPANION.md`  
  Documentation for this companion example. Committed source.
- `primes.w`  
  Canonical CWEB literate source. Committed source.
- `primes.c`  
  Generated by `ctangle primes.w`. Machine-oriented C source. Do not edit manually. Ignored.
- `primes`  
  Compiled executable. Ignored.
- `output.txt`  
  Local captured program output for smoke-checking. Ignored.
- `primes.tex`  
  Generated by `cweave primes.w`. TeX source for the readable document. Ignored.
- `primes.pdf`  
  Generated by `pdftex primes.tex`. Human-readable rendered document. Ignored.
- `primes.idx`  
  Generated index-related file from the weave/PDF process. Ignored.
- `primes.scn`  
  Generated section-related file from the weave/PDF process. Ignored.
- `primes.toc`  
  Generated table-of-contents file from the weave/PDF process. Ignored.
- `primes.log`  
  TeX build log. Ignored.

Generated files are intentionally ignored by this directory's `.gitignore`.
