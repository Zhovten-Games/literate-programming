# Companion

## 1. Short introduction

Jupyter demonstrates notebook-style literate computing. It is not strict Knuth-style WEB and not a tangle/weave workflow. It is an interactive notebook workflow where prose, code cells, execution state, and cell outputs live together in a `.ipynb` document.

In this companion, `primes.ipynb` is the notebook document and `primes.py` is a script companion used for a simple command-line sanity check.

## 2. Source model and compact pipeline

Notebook source:

- `primes.ipynb`

Notebook execution branch:

- `primes.ipynb -> Jupyter kernel / nbconvert --execute -> primes.executed.ipynb`

Script sanity branch:

- `primes.py -> python3 -> output.txt`

Notes:

- `primes.ipynb` is a JSON notebook document.
- `primes.py` is included to make quick script-level verification easy.
- `primes.executed.ipynb` is generated by `nbconvert --execute` and should not be committed.
- Unlike `01-cweb` / `02-noweb-like` / `03-org-babel`, Jupyter does not primarily generate a canonical machine-oriented source file.
- Unlike `04-quarto`, the primary authoring model is an interactive notebook rather than a rendered publication pipeline.

## 3. What Jupyter / .ipynb / kernels / notebook cells are

- Jupyter: interactive computing / notebook ecosystem
- `.ipynb`: JSON document with cells, metadata, execution counts, and outputs
- Kernel: runtime process that executes code and stores state
- JupyterLab / Notebook: browser-based GUI for working with notebooks

The GUI exists, but the reproducible companion check uses command-line execution through `nbconvert`.

## 4. Script sanity-check commands

From this directory:

```bash
python3 primes.py > output.txt
grep "Page 1" output.txt && grep "Page 5" output.txt && grep "7919" output.txt
```

Expected output markers:

- `The First 1000 Prime Numbers --- Page 1`
- `The First 1000 Prime Numbers --- Page 5`
- `      6571      6997      7499      7919`

This confirms that the algorithm and output are correct through a normal Python script path. It does not prove notebook execution; that is checked separately.

## 5. Notebook execution commands

From this directory:

```bash
jupyter nbconvert --to notebook --execute primes.ipynb --output primes.executed.ipynb
grep "Page 1" primes.executed.ipynb && grep "Page 5" primes.executed.ipynb && grep "7919" primes.executed.ipynb
```

Expected markers in the executed notebook:

- `"The First 1000 Prime Numbers --- Page 1\n"`
- `"The First 1000 Prime Numbers --- Page 5\n"`
- `"      6571      6997      7499      7919\n"`

This executes the notebook headlessly and writes `primes.executed.ipynb`, which contains the executed cell outputs.

The Ukrainian branch is structurally validated and passes the script smoke-check; run the documented `nbconvert --execute` command to record notebook-execution evidence before publication. Recorded manual route coverage currently confirms both script and notebook execution in `examples/en/05-jupyter` and `examples/ru/05-jupyter`.


- Jupyter Notebook is the classic notebook interface.

- The reproducible check remains `nbconvert --execute`.

## 7. Why not just comments?

Ordinary comments:

- explanation attached to code.

Jupyter:

- computation and explanation arranged as an interactive notebook.

Important difference: Jupyter is not mainly about extracting source code for a compiler. It is about interactive literate computing.

Hidden state note: notebook cells can be executed out of order, so visible notebook order may not match actual execution history. This is the main reproducibility risk.

## 8. Place in the set

`05-jupyter` shows notebook-style literate computing. It is useful for interactive exploration, teaching, prototyping, and visible cell outputs, but it carries hidden-state and execution-order risks. It is not strict WEB-style source generation. For the full comparison of all companion variants, see the root README.

## 10. Windows notes

Windows is possible but was not the primary tested route for this companion.

- Jupyter can run natively on Windows if Python/Jupyter are installed.
- Tools must be available in PATH.

Check:

```powershell
where.exe python
python --version
python -m jupyter --version
```

If not found:

- install Python;
- add Python/Scripts to PATH;
- install Jupyter into the active environment.

For this companion, the reproducible tested route is WSL/Linux with the shared root `.venv`.

## 11. Troubleshooting notes

A. MissingIDFieldWarning

Manual test warning:

```text
MissingIDFieldWarning: Cell is missing an id field, this will become a hard error in future nbformat versions.
```

This warning means notebook cells are missing stable IDs required by newer `nbformat` expectations. After adding `id` fields to all cells, this warning should disappear.

B. Hidden state

If a notebook works interactively but fails under `nbconvert --execute`, it may depend on hidden state or out-of-order cell execution. The reproducible check should be a clean top-to-bottom execution through `nbconvert`.

C. Kernel/Jupyter not found

If `nbconvert` cannot run:

- activate `.venv`;
- ensure `jupyter` is installed;
- run `python -m jupyter --version`.

D. Generated executed notebook

`primes.executed.ipynb` is generated output and should not be committed.
