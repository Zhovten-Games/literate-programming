# Companion

Цей companion показує практичний noweb-like workflow для одного noweb-like-джерела: `primes.nw`.

## Модель джерела і компактний pipeline

noweb-like-джерело:

- `primes.nw` (канонічне literate-джерело)

Машинна гілка:

- `primes.nw -> notangle -Rprogram -> primes.cpp -> g++ -> primes -> output.txt`

Читабельний/документаційний шар у цьому спрощеному companion:

- читабельним/документаційним шаром є сам вихідний файл `primes.nw`;
- другий згенерований PDF/HTML-документ у цьому прикладі є необов’язковим.

`primes.cpp` навмисно зафіксовано як демонстрацію результату tangling; він має збігатися з результатом такої команди:

```bash
notangle -Rprogram primes.nw > /tmp/primes-from-noweb.cpp
diff -u primes.cpp /tmp/primes-from-noweb.cpp
```

Це чистіше практичне ядро literate programming без повного CWEB/TeX-ритуалу. Воно зберігає іменовані чанки, пояснювальний порядок, кореневий чанк і явний tangling у машинно-орієнтований вихідний текст. CWEB-специфічні угоди про маркери, обов’язковий `cweave`, вимоги до TeX-макросів і генерація PDF як обов’язковий другий етап залишаються поза цим варіантом.

## Машинна гілка: орієнтація на компілятор

```bash
notangle -Rprogram primes.nw > /tmp/primes-from-noweb.cpp
diff -u primes.cpp /tmp/primes-from-noweb.cpp
g++ -std=c++17 -Wall -Wextra -pedantic primes.cpp -o primes
./primes > output.txt
grep "Page 1" output.txt && grep "Page 5" output.txt && grep "7919" output.txt
```

Очікувані маркери у виводі:

- `The First 1000 Prime Numbers --- Page 1`
- `The First 1000 Prime Numbers --- Page 5`
- `      6571      6997      7499      7919`

## Необов’язкова читабельна гілка

Класичний noweb також містить `noweave`, тому окремий читабельний вивід можливий:

- `primes.nw -> noweave -> читабельний вивід у стилі TeX/LaTeX/HTML`

Цей companion навмисно демонструє легший tangle-only шлях, де `primes.nw` сам залишається читабельним документом.

## Маркери і синтаксис чанків (noweb)

- `<<program>>=` визначає іменований чанк із назвою `program`.
- `<<name>>` посилається на інший іменований чанк.
- `@` завершує поточний чанк.
- `notangle -Rprogram` обирає `program` як кореневий чанк.
- `notangle` розгортає посилання на чанки і генерує звичайний C++.
- Компілятор C++ отримує лише згенерований `primes.cpp`, без noweb-маркерів.

## Чому самих коментарів недостатньо?

Звичайні коментарі:

- пояснення прикріплено до коду;
- вихідний текст переважно залишається code-first.

noweb-like:

- код організовано всередині пояснювального джерела;
- іменовані чанки можна вводити у зручному для людського розуміння порядку;
- `notangle` складає ці чанки у машинно-орієнтованому порядку.

Коротка формула:

- Звичайні коментарі: пояснення прикріплено до коду.
- noweb-like: код організовано всередині пояснювального джерела, а потім видобуто для машини.

Такий варіант часто простіше підтримувати в сучасних проєктах завдяки меншій церемоніальності порівняно з CWEB. Іменовані чанки нагадують патерни, знайомі розробникам за блоками коду в Markdown, документаційно орієнтованими прикладами, комірками notebook-документів і executable documents. Підхід зручний для невеликих демонстрацій, алгоритмічних нотаток, навчальних матеріалів і точкових еталонних реалізацій.

Межі зіставлення такі: CWEB історично ближчий до Кнута і сильніший як повноцінна tangle/weave-система; noweb-like легший і краще підходить як основний C++-приклад перезапуску ідеї в цьому companion-наборі.

## Встановлення: перевірений маршрут Debian/Ubuntu/WSL

Цей workflow передусім орієнтований на Unix-like середовище. На Windows практичним шляхом є WSL.

Встановлення інструментів:

```bash
sudo apt update
sudo apt install noweb build-essential
```

Перевірка:

```bash
command -v notangle
command -v noweave
```

Додатково:

```bash
notangle -V
```

`notangle -V` є необов’язковим; визначальна перевірка полягає у тому, що `command -v notangle` повертає шлях.

`noweb` часто не встановлено за замовчуванням. За можливості його варто встановлювати з пакета операційної системи. Upstream README також рекомендує пакетне встановлення, оскільки складання з вихідних текстів може бути застарілим, крихким і надмірно складним.

Примітка про line endings (Windows/WSL): CRLF у `.nw` може створювати візуальний шум у diff або CR-артефакти в результаті tangling. У цьому companion-каталозі `.nw` і згенерований `.cpp` мають використовувати LF. За потреби:

```bash
sed -i 's/\r$//' primes.nw
notangle -Rprogram primes.nw > primes.cpp
```

У цьому каталозі також використовується `.gitattributes`, щоб утримувати потрібні файли у стабільному LF-форматі.

## Файли, що з’являються

- `COMPANION.md`  
  Документація цього companion-прикладу. Фіксується в репозиторії.
- `primes.nw`  
  Канонічне noweb-like literate-джерело. Фіксується в репозиторії.
- `primes.cpp`  
  Генерується командою `notangle -Rprogram primes.nw`. Навмисно зафіксований як приклад tangled-output. Ручне редагування дозволене лише під час регенерації або синхронізації прикладу.
- `primes`  
  Скомпільований виконуваний файл. Ігнорується.
- `output.txt`  
  Локально збережений вивід програми для smoke-check. Ігнорується.

На відміну від `01-cweb`, цей спрощений companion не створює `primes.tex` або `primes.pdf` як частину обов’язкового workflow.
